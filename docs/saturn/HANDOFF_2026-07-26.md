## 2. The finding that reframes the work

**`resolve_triangle` (`src/port/saturn/gfx/saturn_fast3d_frontend.c:450-563`)
is the bottleneck, and it is our own file — not the engine tree.**

It is written in `float`, runs **per triangle corner rather than per vertex**,
and **re-decodes the Q16.16 MVP matrix back to `float` on every corner of
every triangle**. Measured from the ELF: 1,320 instructions, **66 of its 70
`jsr`s are soft-float calls**, 37 inside a loop GCC did not unroll. That is
**~325,851 soft-float calls per frame from one function**.

It was invisible because the PC histogram resolves samples to the libgcc
*leaf*, not the caller. "82.4% soft-float" and "the frontend is 1/34 samples"
were the same cycles counted at opposite ends.

The comparison that matters is internal:

| | cycles/primitive |
| --- | ---: |
| Shipping Saturn engines (SlaveDriver, Z-Treme, SGL) | ~500–660 |
| **Our own castleviewer** | ~1,741 |
| **Our sourceboot** (at 0.36 FPS) | **~83,000** |

Sourceboot was **52× worse than our own other target**; castleviewer sits only
3.5× off shipping budgets. The renderer architecture is not 30× wrong. The
sourceboot data path is.

Compounding, all measured: **1.81× redundancy** (6,933 corner transforms for
3,833 vertices — upstream `gfx_sp_vertex` already does this right); **51% of
transform work discarded after being paid for** (culling after the perspective
divide); and `-DF3DEX_GBI_2E` forcing `GBI_FLOATS`, which is *why* the
transform is float at all.

Full study: [`SHIPPING_ENGINE_COMPARISON.md`](SHIPPING_ENGINE_COMPARISON.md).

### Half the win is available bit-exactly, before any format change

**Of the 325,851 calls, 164,376 — exactly 50% — are the loop-invariant
Q16.16→float MVP decode**: 12 matrix entries recomputed on every corner inside
a rolled loop. Caching it per matrix change is **84 decodes per frame instead
of 6,933**.

That change is **bit-exact**. No format change, no precision change, no
behavioural gate — it validates against this project's strictest acceptance
bar rather than a tolerance-based one. **Do this before the Q16.16 rewrite.**
It is cheaper, safer, and worth half the total.

Two further notes for whoever takes it on:

- **soft-fp under-delivered for a reason that reverses here.** It got 1.65× on
  the float subset rather than 3×, because its code is 2.6× larger than
  fp-bit's against a **4 KB unified cache**. Converting to integer math removes
  both the calls *and* that cache pressure, so the Q16.16 conversion may
  over-deliver where soft-fp under-delivered.
- **`/ 65536.0f` already compiles to a multiply**, not `__divsf3`. The function
  holds one `__divsf3` — the perspective divide. Per corner the cost is
  `__floatsisf` + `__mulsf3` dominated.

### Two live bugs found in passing, not fixed

- **`guMtxIdent()` (`lib/src/guMtxF2L.c:101-108`) writes raw IEEE floats into
  the Q16.16 wire**, bypassing conversion. Confirmed in capture:
  `dbg_root_mtx_decoded_m22 = 0x3F800000`. Every HUD identity matrix loads as
  16,256.0. Likely the remaining source of `dbg_mp_compose_overflowed_ever`.
  Engine-tree file — needs port-side interception, not an edit.
- **`quad_map_bind` linear-scans the whole table in uncached cart memory** on
  all 239 display-list entries per frame, to serve 86 merges.

**Jo Engine non-adoptions** — checked and rejected, do not re-adopt:
`jo_fixed_dot` (miscompiling `mac.l` constraints), `jo_matrix_mul` (accumulates
fixed-point into a `float`), `jo_fixed_pow` (returns x^(n+1)), all trig, and
the entire `jo_3d_*` layer (wraps a proprietary SGL binary). Its DIVU sequence
(`math.c:109-144`) is **pattern-only** and must be split start/collect — Jo's
version stalls the full 39 cycles, the exact thing SlaveDriver and SGL avoid.

### On Z-Treme's no-sale clause — and ours

Z-Treme was briefly shelved as licence-contradictory. **That reading was
wrong.** Its GPL-3.0 grant covers the team's own code and is clean and
ordinary. The no-sale clause concerns **Sonic**, which they do not own — an
acknowledgment that selling would infringe Sega's rights, not a restriction on
their code. They could not license those rights in either direction.

**This project is in the identical position with Nintendo.** The port code is
freely licensed; the IP is not ours; it cannot be sold for that reason rather
than any licensing one.

The generalisable lesson: **a no-sale note in a fan-homebrew repo is usually
an IP disclaimer, not a licence term.** Check which before shelving a
reference — this one cost several hours on the wrong reading. Full record in
[`THIRD_PARTY_LICENSES.md`](../../THIRD_PARTY_LICENSES.md).

### Lessons only — never copy

| Repo | Why | What it taught |
| --- | --- | --- |
| **`sm64-psx`** | **No licence file** at pin `27d80c0…` → all rights reserved. More restrictive than GPL. | Answered the crux: they modified **~112 engine-tree files**, did **not** swap the `f32` typedef, used Q20.12, and kept a hand-written soft float permanently. The cheap typedef-swap hope is dead — someone tried. |
| `fast64` | GPL-3.0 | Per-bone DL splitting. Usable under the GPL policy; nothing needed yet. |

**The tool-only carve-out matters:** `THIRD_PARTY_LICENSES.md` states *"Tool-only
use does not impose a license on this repository's independent Saturn target."*
A GPL-derived **host tool** becomes GPL itself; generated data and the ROM are
unaffected. GPL prior art is therefore cheap for offline tooling and expensive
for runtime code.

## 5. Corrections — figures that were wrong and what killed each

| Claim | Corrected to |
| --- | --- |
| "~7 FPS" | That was **castleviewer/m4**, which stages a pre-baked IR into work RAM. Sourceboot was never measured at that rate. |
| "0.378 FPS baseline" | 0.3596 (pre-quad-merge binary), and now **0.5320** after soft-fp. |
| "14,700 cycles/triangle" | That is the **post**-soft-float residual. It was ~83,000. |
| "The cart/A-bus is the bottleneck" | **Refuted arithmetically.** 75.9 M cycles from ≤190 KB needs 1,598 cycles/longword; A-bus costs tens. Real bug, ~0.8% of that frame — but 60–150% of a 33 ms frame, so it returns later. |
| "`telemetry_decode.py` is broken" | It was **correct**, refusing data that was never the profile. The renderer profile simply had no decoder. Now it does. |
| "82.4% soft-float, high confidence" | Only **7 of 34** PC samples came from current-generation builds; cross-build symbol resolution was unsound. Direction held; precision did not. |
| "soft-fp will give ~3×" | **1.65×** on the float subset, 1.479× overall. Upstream's 3× was SH4 with a 16 KB I-cache; the SH7604 has 4 KB unified. |
| "Jo Engine is BSD-3-Clause-only and attributed to Ponut64" | **Wrong.** The repository root is MIT and `jo_engine/math.c` carries a BSD-style file-local notice; both are © Johannes Fetz. Ponut64 authors `SCSP_poneSound`, a different repository. |
| "Z-Treme is licence-contradictory" | **Clean GPL-3.0.** The no-sale clause is an IP disclaimer about Sonic. |

**The generalisable lesson:** every one of these survived because it was
plausible and documented. The ones that died, died to arithmetic or a
programmatic decode. Prefer those over plausibility.

## 6. Next steps

1. **Cache the loop-invariant MVP decode in `resolve_triangle`.** Half the
   function's soft-float calls, **bit-exact**, no behavioural gate. The
   cheapest large win available.
2. **Then convert `resolve_triangle` to Q16.16**, folding in per-vertex
   transform (1.81× redundancy) and cull-before-divide (51% wasted). Reference
   implementation already at `castleviewer/main.c:434-491`. Acceptance is a
   behavioural gate — positional divergence, identical `gGlobalTimer`,
   counters ±1% — not bit-exactness.
3. **Merge `fix/sourceboot-pool-leak`** before it drifts further.
4. **Stage 0 instrumentation** — phase timers and a multi-stop, ELF-hash-tagged
   PC sampler. **Per-soft-float-call cycle cost is still unmeasured** and gates
   every estimate in the soft-float spec.
5. Textures, then cart staging. Both designed; neither urgent until the frame
   is fast.

**Re-run `-O2` after step 2.** It bought only +2.1% because it cannot
recompile `libgcc.a` — 82% of the frame was in prebuilt code the flag never
reached. Once the float work is gone the proportions invert, and the flag is
one character in `src/port/saturn/sourceboot/Makefile:94`. It was reverted for
costing 77,728 bytes (57% of the HWRAM margin), so re-evaluate the space too.

## 7. Workflow footguns

- **`git commit` takes the whole index, not just what you added.** A concurrent
  session's staged work will be swept into your commit. **Check `git status`
  before committing on a shared branch** — this happened on 2026-07-27:
  `bcf5cfc` is a docs commit that actually contains the entire soft-fp
  implementation. Correct code, wrong message; history was not rewritten
  because a second session was committing concurrently.
- **msys64 starts at `/home/estee`, not the repo root**, and env vars do not
  survive the Git-Bash boundary. Always `cd` explicitly in the *same*
  invocation as sourcing `.yaul.env`.
- **`pytest` is not installed.** Tests are `unittest` via `verify-tools`. Bare
  module-level `test_*` functions are **silently never executed**.
- **Captures take 15–20 minutes.** Run as one foreground command with a 1700s+
  timeout. **Do not background a capture behind a polling monitor** — that
  pattern repeatedly failed to surface completion and cost hours. A plain
  backgrounded shell command with the harness's own notification works.
- **Never run a capture concurrently with a build, or two captures at once.**
- **`post_poke_frames` 12000 → 36000** is the good measurement span (36,000 is
  a hard cap in `capture_hwtest.py`); ±0.7% versus ±1.7%.
- **A complete frame requires `triangles_vdp1_emitted > 0`.** `frame_serial`
  is stamped at submit *start*, so a mid-submit sample reads the right frame
  with partial counters. Sweeping blindly is expensive; fitting `frame_serial`
  against known-partial samples finds the gap between submits in one try.
- **`--probe-count` is a byte count.** `sizeof(profile)` grows — read it from
  the header and decode with `fast3d_profile_decode.py`.
- **Resolve `_sourceboot_fast3d` fresh every build**; the address moves.
- The **linker `ASSERT`** in `sourceboot-cart.x` (≥4,096 bytes HWRAM) exists
  because this project already shipped a silent overrun that corrupted low
  memory before `main()`. If it fires, **stop** — do not weaken it or shrink an
  unrelated buffer.

## 8. Standing rules worth restating

- **The user's eyes are the acceptance gate.** No `TIMELINE.md` or gallery
  entry before visual confirmation. This project has twice mis-identified an
  on-screen object from inference.
- **Source authority, not source immutability.** Prefer port-owned boundaries,
  but permit minimal, scene-neutral `TARGET_SATURN` changes when measured
  evidence shows that a boundary is insufficient or materially expensive.
  Preserve SM64 gameplay and asset semantics, and require a differential or
  behavior test for every exception. The current contract is
  `ENGINE_PORT_ARCHITECTURE.md`; broad PS1-style source divergence remains out
  of scope.
- **Mutation-test before trusting a test.** Multiple mutations survived first
  attempts this cycle and forced real test improvements.
- **Measure; do not estimate.** Two hand-counts disagreed on a must-be-zero
  gate and only a programmatic decode settled it.
- **Defensive guards earn their keep.** The cross-display-list corruption bug
  was caught by a range guard that had previously survived mutation testing as
  *unreachable* defence-in-depth. Keeping it turned silent geometry corruption
  into a counted number.
- **Report negative results plainly.** `-O2` (+2.1%) and double-precision
  elimination (0.0%) were both measured and reverted. Knowing what does *not*
  work is what made the `resolve_triangle` finding legible.
