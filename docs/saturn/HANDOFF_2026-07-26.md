## 2. The finding that reframes the work

**`resolve_triangle` (`src/port/saturn/gfx/saturn_fast3d_frontend.c:450-563`)
is the bottleneck, and it is our own file.**

It is written in `float`, runs **per triangle corner rather than per vertex**,
and **re-decodes the Q16.16 MVP matrix back to `float` on every corner of
every triangle**. Measured from the ELF: 1,320 instructions, **66 of its 70
`jsr`s are soft-float calls**, 37 inside a loop GCC did not unroll. Against
real counters that is **~325,000 soft-float calls per frame from one
function** — 40–85% of the entire frame.

It was invisible because the PC histogram resolves samples to the libgcc
*leaf*, not the caller. "82.4% soft-float" and "the frontend is 1/34 samples"
were the same cycles counted at opposite ends.

The comparison that matters is internal:

| | cycles/primitive |
| --- | ---: |
| Shipping Saturn engines | ~500–660 |
| **Our own castleviewer** | ~1,741 |
| **Our sourceboot today** | **~83,000** |

Sourceboot is **52× worse than our own other target**; castleviewer is only
3.5× off shipping budgets. The renderer architecture is not 30× wrong. The
sourceboot data path is.

Compounding, all measured: **1.81× redundancy** (6,933 corner transforms for
3,833 vertices — upstream `gfx_sp_vertex` already does this right); **51% of
transform work discarded after being paid for** (culling after the
perspective divide); and `-DF3DEX_GBI_2E` forcing `GBI_FLOATS`, which is
*why* the transform is float.

Full study: [`SHIPPING_ENGINE_COMPARISON.md`](SHIPPING_ENGINE_COMPARISON.md).

**Jo Engine non-adoptions** — checked and rejected, do not re-adopt:

generated data and the ROM are unaffected. That is what makes GPL prior art
cheap for offline tooling and expensive for runtime code.

## 5. Corrections — figures that were wrong and got fixed

Today produced several. Trust the right-hand column.

| Claim | Corrected to |
| --- | --- |
| "~7 FPS" | That was **castleviewer/m4**, which stages a pre-baked IR into work RAM. Sourceboot was never measured at that rate. |
| "0.378 FPS baseline" | **0.3596** — 0.378 came from a pre-quad-merge binary. |
| "14,700 cycles/triangle" | That is the **post**-soft-float residual. Today is **~83,000**. |
| "The cart/A-bus is the bottleneck" | **Refuted arithmetically.** Explaining 75.9M cycles from ≤190 KB needs 1,598 cycles/longword; A-bus costs tens. Real bug, ~0.8% of today's frame — but 60–150% of a 33 ms frame, so it returns later. |
| "`telemetry_decode.py` is broken" | It was **correct**, refusing data that was never the profile. The renderer profile simply had no decoder. Now it does. |
| "82.4% soft-float, high confidence" | Only **7 of 34** PC samples come from current-generation builds; cross-build symbol resolution was shown unsound. Direction holds; precision does not. |
| "Jo Engine is MIT" | **BSD-3-Clause.** |

**The generalisable lesson:** every one of these survived because it was
plausible and documented. The ones that died, died to arithmetic or a
programmatic decode. Prefer those.

## 6. Next steps

1. **Resolve the staged soft-fp change.** Commit or revert on evidence.
   Expect ~1.5×, not the 3× upstream figure — that was measured on SH4 with a
   16 KB I-cache; soft-fp's code is **2.6× larger** than fp-bit's and the
   SH7604 has a **4 KB unified** cache.
2. **Convert `resolve_triangle` to Q16.16.** The headline. One port-owned
   file, reference implementation already in `castleviewer`. Fold in
   per-vertex transform and cull-before-divide. Validate with the
   host-differential pattern; the acceptance bar is a behavioural gate
   (positional divergence, identical `gGlobalTimer`, counters ±1%), not
   bit-exactness.
3. **Merge `fix/sourceboot-pool-leak`** before it drifts further.
4. **Stage 0 instrumentation** — phase timers and a multi-stop, ELF-hash-tagged
   PC sampler. **Per-soft-float-call cycle cost is still unmeasured** and it
   gates every estimate in the soft-float spec. Highest-value hour available.
5. Textures, then cart staging. Both designed; neither urgent until the frame
   is fast.

**Sequencing note:** #2 removes ~325,000 soft-float calls per frame — most of
what #1 speeds up. Landing #2 first shrinks #1's value considerably. #1 is
still worth keeping (cheap, bit-exact, already verified), but it is the
supporting act.

## 7. Workflow footguns

- **msys64 starts at `/home/estee`, not the repo root, and env vars do not
  survive the Git-Bash boundary.** Always `cd` explicitly in the *same*
  invocation as sourcing `.yaul.env`.
- **`pytest` is not installed.** Tests are `unittest` via `verify-tools`.
  Bare module-level `test_*` functions are **silently never executed**.
- **Captures take 15–20 minutes.** Run as one foreground command with a
  1700s+ timeout. **Do not background a capture behind a polling monitor** —
  that pattern repeatedly failed to surface completion today and cost hours.
  A plain backgrounded shell command with the harness's own notification
  works.
- **Never run a capture concurrently with a build, or two captures at once.**
- **`post_poke_frames` 12000 → 36000** is the good measurement span (36,000 is
  a hard cap in `capture_hwtest.py`); gives ±0.7% versus ±1.7%.
- **`--probe-count` is a byte count.** `sizeof(profile)` grows — read it from
  the header, and decode with `fast3d_profile_decode.py`.
- **Resolve `_sourceboot_fast3d` fresh every build**; the address moves.
- The **linker `ASSERT`** in `sourceboot-cart.x` (≥4,096 bytes HWRAM) exists
  because this project already shipped a silent overrun that corrupted low
  memory before `main()`. If it fires, **stop** — do not weaken it or shrink
  an unrelated buffer.

## 8. Standing project rules worth restating

- **The user's eyes are the acceptance gate.** No `TIMELINE.md` or gallery
  entry before visual confirmation. This project has twice mis-identified an
  on-screen object from inference.
- **The engine tree stays unmodified** — `src/engine/`, `src/game/`,
  `levels/`, `actors/`, `include/`, `lib/src/`. Intercept at a boundary
  instead. `sm64-psx` shows what abandoning this costs: ~112 files.
- **Mutation-test before trusting a test.** Multiple mutations survived first
  attempts today and forced real test improvements.
- **Measure; do not estimate.** Two hand-counts disagreed on a must-be-zero
  gate this week and only a programmatic decode settled it.
- **Defensive guards earn their keep.** The cross-display-list corruption bug
  was caught by a range guard that had previously survived mutation testing
  as *unreachable* defence-in-depth. Keeping it turned silent geometry
  corruption into a counted number.
