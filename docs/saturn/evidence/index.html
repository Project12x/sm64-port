Caching view-space and projected coordinates for all 424 Mario vertices removed repeated transforms but expanded the target's hot static footprint and produced a deterministic black frame. The pass is rejected and the code was removed; the failure reinforces the internal-WRAM budget boundary.

106 · Zero-growth actor hot path

Animation-bank selection moves out of inner loops

The target now selects the active SM64 animation frame once per game frame. Visibility, painter ordering, Gouraud generation, and VDP1 command emission reuse that pointer instead of repeatedly branching and taking frame moduli. The accepted framebuffer hash is exactly unchanged from the preceding Castle build.

107 · Persistent VDP1 command prefix

Only live commands cross into VDP1 VRAM

The command arena is cleared once at startup. Each frame now clears only the preceding END marker, overwrites the live commands, and uploads the used prefix. The captured view uses 1,105 of 1,627 slots: 35,360 rather than 52,064 bytes, a 16,704-byte (32%) reduction per submission, with an identical framebuffer hash.

108 · Single-pass visible-list walk

The sorted layer boundary eliminates a second scan

Source sorting already appends transparent decals after the opaque/Mario domain. The command builder now retains that boundary and visits each visible item once instead of scanning the entire list twice and rechecking every material layer. The deterministic framebuffer remains byte-identical.

116 · E0 command arena extracted

Shared ownership, identical Saturn pixels

A scene-neutral bounded arena now owns the fixed setup prefix, live command count, prior END marker, peak use, and overflow state while pinned Yaul still encodes and uploads VDP1 commands. The native SH-2 build passes and this deterministic Ymir frame exactly matches Stage 115: framebuffer d145…4f77, PNG ca1601…22ab. This closes E0’s pixel-identity gate and leaves E1’s shared Castle/turntable backend next.

117 · E1 shared backend clients

Castle and turntable share the Saturn submission core

Both SH-2 targets now use one scene-neutral persistent command-list backend and one bounded VDP1 texture-residency destination. The Castle ISO and framebuffer remain exactly identical to Stage 116, while this independent turntable boot proves a second live renderer client. The next E1 cut replaces the turntable’s private depth buckets with common source-identified render jobs.

121 · Gouraud shading — real vertex lighting

The colors were never colors

SM64 runs G_LIGHTING globally, so under lighting a vertex's trailing bytes are a packed s8 normal, not RGBA — the frontend had been painting with misread normal vectors, which is exactly what stage 120's garbage patchwork was. A seven-task sprint built the real path: a Q16.16 light evaluator mirroring gfx_pc.c's semantics, light-command decode, G_VTX gated on G_LIGHTING, per-corner colors through the resolved triangle, and VDP1 CC_GOURAUD tables DMA-uploaded per frame. 2,426 lit vertices vs 36 unlit; 0 bank overflows (VDP1 VRAM was re-partitioned for 1,536 tables — Yaul's stock 1,024 would have overflowed on every ordinary frame). Still untextured by design; what changed is coherent shading instead of noise. User-confirmed.

120 · Q16.16 render-matrix pipeline

BOB's cannon and terrain in free roam

The SH-2 toolchain's soft-float path was proven (host-vs-target differential test) to corrupt the camera matrix every frame, rejecting ~96% of triangles. A six-task sprint replaced the render-matrix path with Q16.16 fixed point — SGL's own FIXED format. The corruption counter fell 392 to 0, emitted triangles rose 18 to 180, and this untextured flat-shaded frame is the project's first visible free-roam gameplay. User-confirmed: the BOB cannon and starting terrain.

119 · First source geometry through VDP1

The unmodified game loop reaches the screen

Original SM64 source geometry, submitted by the real thread5_game_loop and lowered by the shared Fast3D-to-VDP1 frontend, is visible for the first time — untextured and flat-shaded per the gate's labelling. Captured from a cart-enabled boot during the intro sequence; free-roam frames remained blank until the matrix corruption (stage 120) was fixed.
