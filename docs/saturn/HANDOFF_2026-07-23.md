## What shipped this session: the Q16.16 render-matrix sprint

Root cause recap (full chain in the evidence doc above): the pinned SH-2
toolchain (GCC 14.3.0) miscompiles SM64's own unmodified soft-float
`mtxf_lookat`/`mtxf_mul` — proven by the host-vs-target differential test
(`tools/saturn/mtxf_lookat_host_diff_test.c`) — corrupting the render graph's
first matrix every frame and rejecting ~96% of triangles. GCC 15.2.0
miscompiles the same function differently at `-Os`, so upgrading was not a
fix. The sprint therefore made the render-matrix path integer-only. Gameplay
float math (Mario physics, collision, camera decisions) deliberately stays
float — empirically working, out of scope.

Commits, in task order (each task went through implementer +
spec-compliance review + code-quality review with fresh subagents; **every
task's review caught at least one real defect**, all fixed and re-verified):

**Caveat, reported honestly:** the profile struct is memset every frame, so
`triangles_vdp1_emitted = 0` is a one-frame snapshot at frame 233, not a
session total. The screenshot — captured at a different frame in the same
run — shows real geometry, so the two are not contradictory: at the probed
frame nothing reached VDP1, at the screenshotted frame it plainly did. The
screenshot is the first non-uniform frame this project has ever captured,
and the user confirmed by direct visual review that it shows the Bob-omb
Battlefield cannon and starting terrain, untextured/flat-shaded.

## Open items carried forward

1. **`dbg_mp_compose_overflowed_ever = 1`** in the capture — a persistent
   one-way latch meaning some modelview-projection compose overflowed at
   least once at some point in the run. Raw fact, uninvestigated. Worth a
   targeted look before it is assumed benign.
2. **The Q16 wire-format producer/consumer "cannot desync" guarantee is
   emergent, not compile-time.** `src/game/rendering_graph_node.c` and
   `lib/src/guMtxF2L.c` gate on `TARGET_SATURN` alone while the frontend
   gates on `SATURN_MTX_IS_Q16`; today the Makefiles keep them matched. A
   tracked background task exists to gate the producers on
   `SATURN_MTX_IS_Q16` too.
3. **`castleviewer`'s Makefile compiles the frontend without
   `F3DEX_GBI_2E`/`SATURN_MTX_IS_Q16`.** Safe today — it does not compile
   the producer and does not produce real Gfx lists — but a dormant concern
   if that ever changes.
4. **Reporting the GCC 15.2.0 `-Os` miscompilation upstream** remains an
   unclaimed follow-up (evidence is already written up in the toolchain
   evidence doc).
5. Everything carried forward, unresolved, from the 2026-07-22 handoff's
   own "Known limitations" and "Follow-up outside this session's scope"
   sections (no texturing/Gouraud, no polygon clipper, non-full-height
   viewports, the Boo-milestone re-verification, etc.) remains open except
   where superseded above.

## Next implementation

1. **Texture decode** — `G_SETTIMG`/`G_SETTILE`/`G_LOADBLOCK` handling in
   the Fast3D frontend so the now-visible geometry stops being flat-shaded.
2. **Audio — equal priority, not deferred.** Per standing user instruction,
   adapting sound (SCSP-backed, replacing
   `src/port/saturn/sourceboot/source_audio_stub.c`) is just as important
   as graphics now that rendering works. Do not sequence it behind
   texturing by default.
3. **Performance** — the game currently runs in the ~1 fps class; wholly
   unoptimized.

Gameplay float math stays float unless evidence says otherwise.
