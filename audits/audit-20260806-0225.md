## Findings

### Critical

### Important

1. The incompatible S64F record expansion is still advertised as version 1. `FAMILY_RECORD_STRUCT` changed from 13 to 14 words and the C record size changed from 52 to 56 bytes, but both producer and consumer retain version 1. Old and new payloads therefore share an identity while being mutually unreadable. Bump the format version or add an explicit record-size/compatible decoding contract, then pin a trusted expected hash for the new format.

2. The C unknown-runtime-bit payload mutation is not resealed. The test flips byte `records_offset + 52` but leaves the payload digest stale, so validation rejects at the SHA check before it can exercise the unknown-bit branch. Recompute the payload digest after mutation, then assert rejection; retain the separate unknown-required-mask API check.

### Minor

1. “13 unsupported records” is ambiguous. The generated facts are 13 unsupported family representatives/reasons covering 14 closure actor records because the checkerboard family represents two behaviors. The report should use those exact nouns/counts.

### Discrepancies between summary and code

The task report says platform/collectible bits are set by an explicit closure requirement, while implementation sets those class bits from `capability_hints`; `capability_requirements` only validates an already-derived bit. Neither field is currently admitted by the v1 closure schema, consistent with the declared open typed-field gate but not with that sentence.
