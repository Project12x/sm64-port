### Important

**1. The licence ledger misattributes Sonic Z-Treme's upstream.**
Plan §4 names `vbt1/sonic-z-treme`. The actual local clone's remote is
`https://github.com/Maxime-XL2/SONIC-Z-TREME.git`, and every prior project
document (`THIRD_PARTY_LICENSES.md`, `SHIPPING_ENGINE_COMPARISON.md`) uses
`Maxime-XL2`. A provenance ledger whose stated purpose is "part of the
implementation record required by the repository's reference-code-first rule"
must name the right upstream — this is exactly the field GPL attribution
depends on. One-line fix, but it must happen before the first close-port
commit cites this table.

**2. `ponut64/SCSP_poneSound` is not cloned, yet the ledger claims specific files were inspected.**
`work/upstream/` contains no `SCSP_poneSound` checkout, but the ledger lists
"Files inspected: `LICENSE`, `PROJ/main.c`, `PROJ/linker`, `PROJ/makefile`,
`jo_demo/pcmsys.c`, `pcmsys.h`" at pin `31782e4c…`. If these were read via the
GitHub web UI during planning, the claim may be true but is not reproducible
from this machine, and Task 10 (which close-ports the driver) has no clone
step. Either clone it at the pin now, or mark the row "inspected remotely,
clone required before Task 10".

**3. The `m68keb-elf` toolchain is not present, and no task installs it.**
The tech-stack line and Task 10 both assume "the configured `m68keb-elf`
tools"; `m68keb-elf-gcc` is not on PATH and no `work/` directory provides it.
Task 10's only related step says "Build it from source with the configured
`m68keb-elf` tools" — there is nothing to configure yet. Task 10 is blocked at
its first step unless a toolchain-bootstrap step is added (the project's
existing `bootstrap-toolchain.*` scripts cover SH-2, not 68K).

**4. The engine-tree rule retirement is a standing-policy change that lacks a recorded owner decision.**
The "never modify the engine tree" rule appears as an inviolable constraint in
every prior spec, plan, and handoff, and violating it was treated as a hard
stop for implementing agents throughout. The replacement (source-authority
rule + five-item exception checklist) is well-constructed — but the diff
retires it on the plan's own authority, with no recorded user approval. This
project's convention for decisions of this weight is an explicit owner
decision recorded in the doc (the Z-Treme adoption in
`THIRD_PARTY_LICENSES.md` is the model: dated, reasoned, attributed).
Recommend the user explicitly confirm, and the architecture doc record
"approved by project owner, 2026-07-27" — before the first engine-tree edit
lands, not after.

## What was done well

- **The measured starting point is real.** Every number in §2 matches the
  independently-decoded captures — nothing was rounded, inflated, or carried
  from a stale document. The plan even inherits the correct 0.6718/0.5320
  distinction.
- **The sm64-psx handling is exemplary.** Behaviour-only status maintained,
  copy/close-port explicitly prohibited, and §3's "Important animation
  correction" catches that `compress_mario_anims.c` performs no compression at
  the pin — refusing to cite the README's size ratio as evidence for an
  algorithm that does not exist. That is precisely the discipline this
  project's corrections table demands.
- **The libyaul-examples caution is verified and correct.** The checkout
  genuinely lacks a root LICENSE; the plan downgraded it to behaviour-only and
  banned copying `sdrv.bin` rather than assuming the GitHub page's licence
  applies to the pin.
- **Gate quality.** Exit gates are falsifiable and counter-anchored
  ("zero float helper calls", "at most once per generation", named overflow
  counters all zero), the 15 FPS gate explicitly forbids relabeling, and gate
  13 (a second area + dynamic actor reload) guards against a BOB-only static
  cache — a failure mode nobody had named yet.
- **The rule replacement, on its merits, is well-designed.** Narrow-delta,
  `TARGET_SATURN`-guarded, five-item evidence checklist per exception,
  scene-neutrality required, differential test required, and it explicitly
  rejects the PS1-style wide fork. The process concern in finding 4 is about
  authorization, not design.
- **Dependency graph and shared-verification sections** mean the twelve tasks
  can actually be dispatched to separate agents without each re-deriving the
  capture recipe — including the don't-capture-during-build rule that cost
  this project hours.
