# Peer Audit — Two Weeks of Saturn Port Development Behavior

Date: 2026-08-12

## Context

This audit reviews the current linear branch from the commit immediately before
2026-07-29 (`83938f3abbc359569191e5ccc068ccce75f83785`) through the frozen Task 7
evidence head (`97dae9b28af9486186cc4c3ccd427b64459a86a0`). It was requested after
the textured-actor sprint again reached a late hardware-ownership redesign
before a manual gate.

The review is deliberately about delivery behavior, not whether individual
tests are rigorous. It uses commit history, net and cumulative diff statistics,
the current plans, and the task execution reports. The worktree is dirty with
the interrupted Task 7 repair and unrelated preserved work, so no uncommitted
repair is treated as completed evidence.

- 888 commits across 14 active commit dates in the two-week window, all on one

  on 2026-08-06.
- Commit subjects: 381 `docs`, 302 `fix`, 94 `feat`, 54 `test`, 33 `perf`, and
  24 other. Documentation plus fixes are 76.9% of all commits; fixes outnumber

- Subject terms include 71 `repair`, 63 `review`, 10 `rereview`, 59 `evidence`,
  63 `close`, and 22 `approve` commits.
- Net diff: 709 files, +282,372/-2,708 lines. Added-line distribution is about
  52.9% documentation/SDD evidence, 32.5% host tools/tests, 11.5% runtime

- Cumulative per-commit churn is +300,810/-21,146 lines. Repeated rewriting
  therefore adds 36,876 changed lines beyond the final net state.
- The current texture sprint alone (`3338de20..97dae9b2`) produced 37 commits
  in about eight hours: 24 documentation, 6 feature, 6 fix, and 1 refactor.
- Across Tasks 1–7 of that sprint, six initial reviews failed. The recorded

## Findings

### Critical

#### 1. The process proves artifacts before it proves that the product can run

The hermetic release sprint successfully built, reproduced, sealed, audited,
and staged a candidate. The immediately following 20,100-frame emulator gate
then showed that the sealed target advanced only to simulation generation 2:
`ACTOR_ADMIT` failed and `ACTOR_LOWER` was quarantined. The production wrappers
were intentional `return false` stubs because the actor cutover was unfinished.
This is recorded in
`.superpowers/sdd/2026-08-10-hermetic-full-game-release-identity/task-10-report.md:7-21`
and `:136-169`.

That sequence is backwards for a port. Reproducibility and provenance are
valuable, but they sealed a target whose accepted feature tuple selected an
unimplemented product path. The manual/emulator gate was used as final
acceptance when it needed to be an early architectural precondition.

Impact: weeks of trustworthy evidence describe a binary that is not yet a
playable integrated slice. Every later target-byte correction reopens the most
expensive build/reproduction/seal work.

Recommendation: no further release reseal or large proof campaign until a
fresh target completes a short live BOB route with advancing simulation,
successful actor jobs, and a captured frame. Run that smoke after each vertical
runtime increment, not at the end of a 9–13 task plan.

### Important

#### 2. The sprint's acceptance witness is materially narrower than “complete BOB”

The current exact artifact contains 47 family records but only 14 supported
drawable S64B-v2 variants. Twenty drawable variants remain explicitly
unsupported: 18 `GEO_SHADOW`, one `GEO_SCALE`, and one `GEO_ASM`. Two more are
`MODEL_NONE` sentinels. These are the authoritative counts in
`.superpowers/sdd/2026-08-12-saturn-actor-bank-v2-textures/task-5-report.md:12-16`.

The design itself says v2 is “full-game-shaped, not semantically full-game-
complete” (`docs/superpowers/specs/2026-08-11-saturn-actor-bank-v2-textures-design.md:26-28`).
The plan nevertheless makes Cannon the mandatory visual witness
(`docs/superpowers/plans/2026-08-12-saturn-actor-bank-v2-textures.md:59` and
`:969-999`). Cannon is a useful pipeline witness, but it is a weak proxy for
the missing scene semantics and does not establish complete BOB.

Impact: the vocabulary suggests level completion while the acceptance gate
proves one selected actor and leaves 20 of 34 drawable BOB variants unsupported.

Recommendation: rename the current milestone “textured actor pipeline witness”
unless its gate is changed to 34/34 drawable BOB variants admitted and rendered.
Do not call the result complete BOB. Do not call the architecture full-game-
capable until a second level exercises the same format without a redesign.

#### 3. Independent review is repeatedly discovering architecture, not checking it

The current sprint's review ledger records six first-review failures across
seven tasks. Findings include unowned header bytes, allocation-before-bound
checks, unattested texture inputs, unauthenticated family reports, incomplete
Make import closure, VRAM address-span wrap, CLUT-local ordinal escape, staging
generation aliasing, corrupt publication acceptance, and direct SCU DMA from a
CART pointer. The current Task 7 report lists the latest four Important issues
at
`.superpowers/sdd/2026-08-12-saturn-actor-bank-v2-textures/task-7-report.md:121-141`.

These are not cosmetic defects. Several change public ownership or dataflow
after implementation: caller-owned HWRAM staging, DMA preflight, publication
validation, import graph ownership, and package provenance. That is precisely
the redesign-at-the-end pattern the user identified.

Impact: code is repeatedly marked `source-complete-pending-review` before its
memory owner, transport boundary, or adversarial input closure has been agreed.
Repair rounds then invalidate estimates and downstream assumptions.

Recommendation: add a mandatory pre-code architecture review for every Saturn
task that crosses CART, HWRAM, LWRAM, SCU DMA, VDP1 VRAM, master/slave
ownership, or generation publication. The review must name source and
destination address spaces, lifetime owner, maximum byte span, alignment,
failure atomicity, and the first real target consumer. A task cannot enter TDD
until that table passes review.

#### 4. The plan chain repeatedly replaces the previous “path to full port”

New governing plans were introduced in rapid succession:

- 2026-08-03: overlapped Saturn render pipeline (`1c262766`)
- 2026-08-05: full-game completeness sprint (`7e0087ff`)
- 2026-08-09: textures + actors memory residency campaign (`c7e6dd3f`)
- 2026-08-10: hermetic full-game release identity
- 2026-08-11: generic actor scene bundles (`a74a3080`)
- 2026-08-12: textured actor-bank implementation (`3338de20`)

Each plan contains sensible local work, but the next plan is repeatedly needed
to supply a prerequisite that the previous plan assumed or deferred. For
example, the sealed release exposed the missing actor cutover; the actor cutover
then exposed missing generic bank materialization; generic banks exposed zero
representable textured BOB variants; textures then exposed residency and DMA
ownership gaps.

Impact: “infrastructure for multiple levels” remains a sequence of local
schemas and proofs without a stable end-to-end slice. The roadmap expands
laterally rather than retiring one playable dependency chain.

Recommendation: freeze new Saturn plans. Maintain one convergence board with
only the shortest dependency chain to one manual BOB gate. Any newly discovered
prerequisite must replace or remove an existing item; it may not create another
parallel sprint with its own completion vocabulary.

#### 5. Commit and documentation granularity obscures milestone truth

The two-week history has 888 serial commits, with 381 documentation commits and
302 fixes. The current eight-hour sprint has 24 documentation commits for six
feature commits. This is not inherently wrong, and the operational ledger is
often excellent, but status churn (`open`, `source-complete`, `repair`,
`approve`, `close`) has become a major product of the work.

Impact: a reader sees many “approve” and “close” transitions while the target,
Ymir, visual, and manual gates remain unchecked. The volume makes it difficult
to identify the few commits that changed executable capability and encourages
local-task completion to substitute for port progress.

Recommendation: keep the ledger, but collapse status-only commits into one
milestone reconciliation commit per reviewed vertical slice. Report two
separate percentages: host-contract completion and playable-gate completion.
Only the latter advances the port milestone.

#### 6. Saturn/SH-2 constraints are being handled seriously, but too late in the sequence

The implementation consistently respects fixed buffers, pointer-free wire
formats, exact generation publication, and fail-closed parsing. However,
hardware topology has repeatedly appeared during review or integration:
cross-tool backend attestation, `/tmp` ownership, CART relocation, SH-2 helper
selection, VDP1 partition arithmetic, and now CART→HWRAM→SCU DMA staging.

Impact: host-format tasks pass extensive mutation suites while the eventual
SH-2 consumer still requires an interface change.

Recommendation: every host format must ship with a minimal freestanding target
consumer and address-space fixture in the same first task. Host generation,
target parse/bind, and one emulator observation should be one vertical unit,
not three successive infrastructure phases.

### Minor

#### 7. “Full-game” and “complete” are overloaded status terms

The documents often qualify the claims correctly in nearby text, but filenames,
plan titles, and commit subjects use “full-game,” “complete,” “release,”
“approve,” and “close” for host-only or infrastructure-only slices. This
creates an avoidable expectation mismatch.

Recommendation: reserve `complete` for an externally observable gate. Use
`host-contract-passed`, `target-linked`, `emulator-smoke-passed`,
`visual-passed`, and `manual-passed` as mutually distinct states.

## Discrepancies

1. The hermetic release was technically reproducible but not behaviorally
   releasable: the next smoke proved an intentional production actor stub.
2. The current sprint headline promises a production textured Cannon demo, but
   current completed evidence is host/freestanding infrastructure and exact
   14/34 drawable support; Task 7 is still in repair, and Tasks 8–13 remain.
3. “Full-game-shaped” describes extensible byte structure, not supported game
   semantics. The history and user-facing discussion have sometimes treated
   those as equivalent.
4. The process says independent review is a completion gate, but most design-
   altering facts are discovered only after an implementation has already been
   declared source-complete.

## What was done well

- Independent reviews are real and effective. They repeatedly found genuine
  safety, provenance, and hardware-boundary defects rather than rubber-stamping.
- Failure handling is unusually disciplined: unknown source states, stale
  generations, mutation, and capacity overflow generally fail closed.
- Historical Mario/v1 byte identities and compatibility gates have been
  preserved carefully through broad refactors.
- The team records exact hashes, target flags, toolchain inputs, memory margins,
  and failed gates honestly. The Task 10 report is an excellent example of not
  blaming the emulator when the product path was incomplete.
- Saturn and SH-2 constraints are treated as first-class design constraints.
  The problem is sequencing, not disregard for the hardware.

## Recommended next actions

1. **Keep Task 7 paused after the current safe repair point and re-baseline the
   milestone.** Do not open Task 8 merely because Task 7 passes review.
2. **Choose the actual milestone explicitly:**
   - If the milestone is a quick pipeline witness, say so and gate one normally
     spawned actor in Ymir immediately.
   - If the milestone is complete BOB, require all 34 drawable BOB variants,
     successful actor jobs, advancing simulation, and a visual capture. Cannon
     alone cannot close it.
3. **Move emulator feedback forward.** After the minimum actor cutover and one
   bank, build and run. Do not first finish every host bundle, residency proof,
   release identity, and reseal task.
4. **Review hardware ownership before implementation.** Require a one-page
   CART/HWRAM/LWRAM/VDP1/SCU ownership and lifetime table for the remaining
   actor path.
5. **Stop creating new governing sprints until the manual BOB gate passes.** A
   new prerequisite must be folded into the single convergence chain.
6. **Use one externally visible progress metric:** number of normally spawned
   BOB drawable variants that render correctly in the current exact build,
   currently 0 target-proven out of 34. Host compilation of 14 is a supporting
   metric, not the milestone.
7. **Only after the visual/manual gate**, restore A/B reproducibility, v4 audit,
   release staging, and broader multi-level generalization.

## Bottom line

The last two weeks did build substantial, reusable Saturn infrastructure, and
the quality mechanisms are strong. But the delivery pattern is not converging
efficiently on a manual port gate. It repeatedly optimizes proof completeness
for a locally scoped subsystem, discovers the next hardware/product boundary
at review or integration, repairs and re-documents it, then opens a successor
plan. The user's description—multiple “path to full port” sprints redesigned at
the end—is supported by the commit and gate history.
